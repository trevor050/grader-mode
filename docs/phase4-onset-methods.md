# Phase 4 exploratory onset methods

This implements only the exploratory token-level onset paragraph of DESIGN.md Phase 4. It does not generate responses, estimate H15–H17, change prompts, select new neurons, or change the Phase 3 scale. The separate execution allowance is **$1.50 aggregate Modal spend**, including failed attempts. No Vast resources are used.

Commands, from the shared main checkout:

```sh

uv run modal run -m src.modal_app_4_onset --run-id phase4-onset-20261021
uv run python -m src.analyze_4_onset --run-id phase4-onset-20261021
```

The frozen reference is Phase 3 at `f223175`, including the neutral-control code and methods. Inputs are `results/raw/phase3-20261020-v2/tracking.jsonl`, its `trajectories.npz`, the Phase 3 manifest, neuron selection, and screen statistics. The original Phase 1b Qwen3-14B cue-none/thinking-on test responses are matched against their original scored labels and the ordered Phase 1 sample. All 400 traces (100 test problems × four templates) are required. Historical Phase 3 source hashes, response hashes, original rendered tutor-prompt hashes, cached trajectory validity, and exact recomputation of the cached neuron selection are checked. DESIGN's historical source hash is checked against its historical commit; the current Phase 4 document is recorded without modification. The current Phase 3 runner must match `f223175` exactly.

Both tutor and neutral contexts are replayed with the pinned Phase 3 model/tokenizer revision, BF16, SDPA, and original four-trace batch order. The neutral context substitutes only the committed `system_neutral.txt`. Full prompt-plus-response text is tokenized first; prompt-prefix token IDs must be unchanged, and every reasoning token in both arms must equal the original saved Phase 3 token IDs before any model forward. There is no new sampling. The frozen tutor and neutral system turns retain their measured 103/96-token lengths; no prompt adjustment is made.

An explicit opening `<think>` token with exact character offsets is required for this boundary analysis. Boundary coordinates are **−64…−1**, the **tag token at 0**, and **1…64** after it. Keeping the tag separately gives 129 boundary positions. The second window retains reasoning tokens **1…256**, strictly inside the original closed reasoning span and excluding tag tokens. Windows overlap intentionally. The newline following `<think>` is a reasoning token when the frozen tokenizer assigns it a token, following the original Phase 3 offset rule. Positions absent in a short trace are masked, never padded into the numerical estimate. The two contexts have separate boundary token-ID arrays because pre-tag prompt tokens may differ; all retained reasoning token IDs must match. The pre-tag window can include system-turn content for short user prompts.

Forwards end immediately after the last retained token, using slices of the fully tokenized original replay. Causal attention ensures later response tokens are unnecessary to measure these positions. Left padding is excluded by explicit positions plus the attention mask. Each arm retains all six scores separately. Scores use precisely Phase 3's input-to-`down_proj` hooks and arithmetic: selected activation minus that neuron's cached tutor-reading mean, divided by its cached tutor-reading SD, summed and divided by 20; float32 accumulation across layers. All five cached layer-matched control sets use their own cached tutor means/SDs, exactly as Phase 3. The tutor-minus-neutral subtraction occurs per trace, position, and set before aggregation. No rescreening, refitting, or control reselection occurs.

`onset-tokens.npz` contains 400 × 385 × six tutor, neutral, and paired-contrast arrays, a boolean availability mask, separate token IDs, and trace IDs. Missing entries are zero storage placeholders governed exclusively by the mask. `onset-traces.json` preserves identity/outcome metadata, token checks, response hashes and rendered-prompt hashes. The execution metrics carry the archive checksum. Analysis requires a completed matching execution, intact package/archive hashes, 400 verified identities, and verified shutdown within the cap.

`onset-positions.csv` reports the mean, unadjusted 95% percentile bootstrap interval, eligible traces, eligible problems, and undefined-resample count at each of 385 positions for the tutor set and five controls. Estimates give each eligible trace equal weight. The bootstrap uses 2,000 whole-problem paired resamples, NumPy `default_rng(0)`, retaining all four templates and all sets/positions together. Every draw recomputes the ratio of contrast sums to eligible trace counts; a draw with no eligible traces is undefined and counted. No outcomes are removed from the overall curves. These are exploratory summaries with no hypothesis tests or multiplicity adjustment.

`onset-windows.csv` additionally reports four predetermined windows: 64 tokens before the tag; 64 after, excluding the tag; first 64 reasoning tokens; first 256 reasoning tokens. Each first averages available positions within trace, then averages eligible traces with the same bootstrap. `onset-summary.md` contains factual counts and tutor window headline values only; the CSVs include all controls. No interpretation is supplied.
