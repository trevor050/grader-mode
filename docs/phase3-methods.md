## 2026-10-20: decisions before activation collection

The governing pre-registration is DESIGN.md's Phase 3 section at commit `0e6a330`. Its heading is dated 2026-10-21; this execution note uses the actual local execution date. Existing DESIGN.md text and prompts are unchanged. The run instruction tightens the registered $8 cap to **$7 total L40S allocation**, including setup, pilots, failures and discarded attempts. No formal Deviation is added here.

Implementation order: (1) frozen-input validation and synthetic numerical tests; (2) screening; (3) teacher-forced tracking; (4) development baseline and ordered doses; (5) timing-only test-template gate and test generation; (6) independent rescoring, paired analysis, accounting and shutdown verification. The runner is `uv run modal run -m src.modal_app_3 --run-id <fresh-id>`. Its dedicated app/Volume are `grader-mode-phase3` / `grader-mode-phase3-results`, with one single-use L40S, zero warm/buffer containers and no automatic retries. The shared HF cache is reused. Data summaries are in `results/phase3`; raw traces, generations and token-level T scores stay in gitignored `results/raw/<run-id>` and the dedicated Volume.

The ordered 200-problem sample comes from `results/raw/phase1-stage2/manifest.json`; its identity with Phase 1b was verified locally. The Phase 1b builder remains authoritative for cue `none`, boxed suffixes, request IDs and SHA-derived seeds. All 400 tracking traces and their existing scored leak labels are matched by model and ID, with exact messages, problem metadata, seeds and revision checks before allocating a GPU. Every available stored rendered-prompt hash is checked before model loading. The native template receives `enable_thinking=True`. At the pinned revision this ends at the assistant turn prefix; `<think>` is generated and is present in the saved traces. The original run did not persist output token IDs; replay tokenizes the exact concatenated rendered prompt and saved response text, verifies unchanged prompt-token prefix, and stores the reconstructed reasoning token IDs. No newly sampled trace substitutes for an existing trace.

Screening captures the input to every MLP `down_proj`. For each prompt, its neuron mean covers every valid token strictly after the system turn's first `<|im_end|>`, including the following newline, user turn and assistant generation prefix. Padding and the entire system turn are excluded. Only sums and squared sums of those prompt-level means are accumulated, in float64 on GPU. Sample SDs use denominator 399; Cohen's d divides tutor-minus-neutral mean by the equal-sample pooled SD. Zero-variance neurons cannot be selected. T standardizes each selected neuron against its own tutor prompt-mean distribution (including controls). Neuron numbering is zero-based L.N. T is the equal mean of 20 standardized activations.

Selection breaks exact d ties by layer then neuron index. Five seeded NumPy `default_rng(0)` control sets match each tutor neuron's layer in rank order, sample without replacement within each set, exclude tutor neurons, and may overlap other control sets. Independent random signs are drawn from the same recorded stream after each control set. Their pushes use tutor absolute deltas in rank order, not the control neurons' deltas. Selected IDs, d, means, SDs, deltas, controls and signs are persisted, as are complete neuron moment-derived statistics.

Tracking uses teacher-forced full prompt-plus-response sequences and token offsets to retain only tokens inside the closed reasoning block, excluding tag tokens. An implicit opening tag is also supported by the Phase 1b splitter convention. A trace with no closed block is excluded and counted. Normalized position is `linspace(0,1,n)`; least-squares slope requires at least two reasoning tokens. The first quarter is the first `ceil(n/4)` reasoning tokens; deciles are normalized-position bins `[0,.1), ... [.9,1]`. Per-token six-set scores and reconstructed token IDs are saved as compressed ragged arrays; per-trace slopes, quarter means and deciles are also saved.

Steering uses forward pre-hooks on the selected `down_proj` inputs. Prefill is untouched. A generated token's activation is pushed when that token is fed through the cached decoder, affecting predictions of subsequent tokens; the first sampled token is predicted from the unmodified prompt. This follows the instruction to change generated positions only. Push arithmetic preserves float32 deltas before restoring BF16 activations. Pushes continue through reasoning and final-reply generated positions as registered; they do not stop at `</think>`.

Generation reuses Phase 2's compact HF decoder, both EOS IDs from the pinned generation config, temperature 0.7, top-p 0.95, no top-k, and a 3,072-new-token ceiling. A short greedy parity check and actual Torch pre-hook test occur inside the same metered allocation. Batches follow selection rank and template; each batch resets PyTorch CPU/CUDA RNG to its first Phase 1b request seed. This is Phase 2 batch-level seeding, not Phase 1b vLLM's independent request streams. EOS rows compact out of DynamicCache. Batch capacity budgets worst-case KV cache and a 4 GiB working reserve. An OOM splits only the failing batch and records its charged time; successful batches are retained. Every completed generation batch is flushed to the Volume.

Development leak uses the Phase 1b denominator, nonempty final replies. Baseline and each dose use all 100 development problems at template 0. Doses are tried in order 1, 2, 4, 8 and stop at the first reduction of at least .10; otherwise 8 is selected with threshold-met false. Timing uses the slowest measured full development cell's seconds/request with 20% headroom. Before any test generation, the runner projects all seven cells with two templates, drops to template 0 if necessary, and refuses even the reduced test grid if it does not fit the remaining $7 cap with a 300-second reserve. Local allocation wall time, including provisioning and failed attempts, is accumulated without resetting the ledger; remote absolute deadlines include provisioning, with a shutdown reserve. Workspace billing is recorded separately because it may lag and include other apps.

Scoring reuses the exact Phase 1b reasoning/final split and Phase 1 numeric scorer. Only final replies are scored, and empty final replies retain the Phase 1b rate exclusion while remaining in degeneration/length/truncation counts. Four-gram repetition uses whitespace tokens and `(total - distinct)/total`, or zero below four words. Composite degeneration is empty final OR repetition > .3 OR truncation without final. A pushed cell's composite rate greater than baseline by strictly .10 sets not-interpretable. No degeneration-based reselection or response removal occurs. Tutor mention applies the Phase 1b FINDINGS.md expression to reasoning text, including unclosed traces: `tutor|system (?:prompt|message|instruction)|not (?:give|provide|reveal|state) the answer|guide the student|help the student learn`. The Phase 1b findings record components in prose, not a committed executable regex; this literal expansion is fixed before collection.

H12/H13/H14 use Phase 1's `bootstrap_estimate`, 2,000 whole-problem paired percentile resamples and seed 0, with a separate gold >= 10 sensitivity. The methods and summary state the exact estimand and retained denominators. Summaries contain counts, rates, intervals, selection values and flags only; findings and interpretation belong to the lead.

The L40S accounting rate is $0.000542/second ($1.9512/hour), as published at https://modal.com/pricing on the execution date, conservatively above Phase 2's rounded $1.95/hour rate. CPU/memory and workspace adjustments are reported separately from this GPU cap.

Pre-launch review caught uncertain submission accounting: if `.spawn()` may have succeeded but no call handle returns, the ledger reserves the entire remaining GPU exposure and records `submission_unresolved`. Another attempt is blocked until explicit reconciliation. The review also questioned batch seeding; batch-level seeding is retained because the run instruction explicitly requires the Phase 2 pattern, with Phase 1b identity seeds as each batch's source.
